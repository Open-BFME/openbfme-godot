# Reloadable console scripts

Put `.lua` entry files directly in this directory, then press **Ctrl+Shift+F5**,
click **Reload scripts**, or run `bfme.console.reload()`.
All files are reread from disk on every reload, in filename order. No restart is required.

Files run in the persistent console VM. Define globals/functions here and call them from
the console; functions with the same names are replaced when reloaded. Existing unrelated
globals remain. Entry-script return values are ignored; automatic event callbacks are not provided.

The included helper provides `setGold(10000)` after reloading. It returns a mutation ticket.

Exported games also read `.lua` files in `user://dev` after the bundled scripts.
On macOS that is `~/Library/Application Support/Godot/app_userdata/OpenBFME/dev/`.
Use that directory for editable scripts in a packaged game. `require()` only loads the built-in `bfme` module and its `bfme.<library>` libraries. `05_skirmish_ai.lua` is the Lua skirmish AI (`luaai.enableAll()`).

All entries are compiled before any run. A syntax error prevents the reload; a runtime
error stops at that file, after any earlier files have already run. Edits are not transactional.

`04_gondor_plots.lua` loads the seven BFME1 Men/Gondor floor textures from local DDS assets.
Import them with `python3 tools/import_bfme2lua_gondor_plots.py --source /path/to/BFME2Lua`
from the repository root. The assets stay in the ignored `godot/mods/gondor_plots/` directory.
Use `gondorPlots.enable(false)` / `gondorPlots.enable(true)` to switch the floors during a match.

## Building layouts

Reload scripts, then use the console in a match:

```lua
recordBuildings("base")                    -- local player's current buildings
recordBuildings("enemy", 2)                -- or an engine player slot
replayBuildings("base")                    -- normal construction, no builders
replayBuildings("base", {level3=true})      -- instantly grant rank 3 when each completes
replayBuildings("base", {player=2, speed=2})
```

Record before destroying the original base, then replay on clear ground (or in a new
match on the same map). The snapshot includes owned starting buildings and walls,
excludes empty foundation/expansion pads, and preserves template, position, rotation,
completed object upgrades and linked wall pieces. Fortress roots are retained even
though their native type also counts as a foundation.
It records buildings that still exist, not a history of destroyed buildings.
Construction charges normal costs and respects native placement checks. Provide
sufficient money with `setGold(...)` if needed. Fortress keeps and pads generated by unpacking are reused, then purchased
expansions are constructed on their matching pads. Walls, gates, posterns and wall
towers are recreated using their final templates; gate side-clearing is not run a
second time. Independent buildings and wall hubs are submitted together, with up to
64 outstanding operations. Linked wall segments and upgrades start as soon as their
hubs exist under construction; they do not wait for hub completion. Fortress
attachments still wait for their parent layout and keep upgrades. No builders are
spawned or required.

`buildingReplay` shows submitted/completed counts, errors and pending tickets.
Completed building upgrades (including fortress improvements) are granted after
construction, without researching or charging for them again. The keep is restored
before expansions so inherited fortress improvements apply. Player-wide research
and unfinished research queues are not recorded.

Unavailable level-3 ranks are reported; structures without an experience tracker
are left alone. `stopBuildingReplay()` stops submitting work; already submitted
construction continues, but further restoration actions stop. Changing matches stops replay.

`recordBuildings("base")` automatically saves `user://building_layouts/base.json`.
Replay loads the saved file automatically when the layout is absent from memory.
Use `saveBuildings("base")` after manual edits, `loadBuildings("base")` to reload
from disk, and `listBuildingLayouts()` to list saved names. Names use letters,
digits, underscores and hyphens (maximum 80 characters). Recording the same name
replaces its file. Files contain a version and all recorded building data,
including upgrades, pads and wall links, and survive app restarts.

On macOS the folder is `~/Library/Application Support/Godot/app_userdata/OpenBFME/building_layouts/`.
`exportBuildings("base")` remains available for a portable Lua assignment.

## Neutral scenery placement

`neutral_decorations.lua` enables construction over neutral, non-capturable scenery
buildings in local matches. Preview ignores those obstacles; confirming construction
clears only overlapping scenery. Capturable sites, lairs, production/economy
structures, fortresses, walls and player-owned buildings are protected.
Use `neutralDecorations.enable(false)` to disable, or `.enable(true)` to restore.
The script applies the option again when a new match starts. Network games and
replays are excluded. Reload scripts after installing; the native engine must also
be rebuilt for the placement hook.
