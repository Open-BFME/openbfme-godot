## Recovered C++

Member names below are descriptive adapters except donor class names.
Signed-vs-unsigned comparisons are deliberate. No random draw occurs.

```cpp
// RW 0x8F0502..0x8F0601
void AIBaseBuilder::saveMoney()
{
    uint32 frame = TheGameLogic->getFrame();
    if (m_nextSaveFrame > frame) return; // unsigned, RW 0x8F0514
    AIEconomyStats *economy = playerInfo(m_owner)->economy;
    int count = economy->size(); // RW 0x945ADA
    int difficulty;
    if (m_owner->getDifficulty() > 1) difficulty=2;
    else difficulty=m_owner->getDifficulty(); // called twice on this path
    // RW 0x8F055A..0x8F0586: signed JG max, unsigned JNC reserve check.
    int cap = maxSigned(m_capDemand, mul32(difficulty,5000));
    economy->m_cap = uint32(cap);
    if (cap == -1 || economy->m_saved < uint32(cap)) {
        AIBrain *brain = lookupBrain(m_owner);
        // RW 0x8F05AA..0x8F05DE: keep x87 intermediates until ftol2.
        auto fraction = x87div(brain->config->PercentToSave[brain->index],
                               signed32(3-difficulty));
        auto amount = x87mul(unsignedToX87(m_owner->money),fraction);
        if (amount > 1.0 && count > 2)
            economy->rva005963A1(ftol2(amount)); // RW 0x99E773
    }
    // RW 0x8F05EF..0x8F05F7, regardless of whether saving happened.
    m_nextSaveFrame = frame + 2u*LOGICFRAMES_PER_SECOND;
}
```

`maxSigned` is essential: Ghidra's unsigned-looking temporaries obscure the
JG at RW 0x8F0574. Difficulty is capped above at 2, not clamped below at 0.
The cap is overwritten every due call. A reached cap or too few economy
objects still reschedules; a future frame returns without touching anything.
Tick arithmetic wraps modulo 2^32, using a plain unsigned comparison, not a
wrap-aware elapsed-time helper. LOGICFRAMES_PER_SECOND comes from RW 0xD9F608.

The ratio, unsigned-money conversion and product are x87 operations under
the game's precision control: signed FILD plus float 4294967296 at
RW 0xBD8698 for high-bit unsigned values. The product is compared strictly
above one (unordered also fails) before truncating through __ftol2
RW 0xA3CFA4. Do not introduce a float32 store between divide and multiply.

The matched callee AIEconomyStats::rva005963A1 in
Common/Rva0025BFE3Derived.cpp implements the actual transfer. The caller
does not clamp the amount to remaining cap room; its only cap gate is the
pre-transfer comparison. Reproduce the callee rather than assuming saving
just adds a counter.

Specifically, for a nonzero uint32 amount the matched callee withdraws that
amount from its stored Player +0x90 Money with (amount, null score, true),
then adds the requested amount to saved balance +0x14. It does not use the
withdraw return value to decide the saved increment.

## Port disposition

The coupled reserve path was integrated by lane AI5 on current main into `AIBaseBuilder` and the
per-player `AIStatCollector` (the existing owner of the economy object list):

- RW 0x99E738 initializes saved money to zero and cap to unsigned -1.
  RW 0x99E766 adds money + saved with 32-bit wrapping. RW 0x99E79A withdraws
  all-or-nothing when requested <= saved, depositing to Money without score.
- RW 0x8F113F calls the saver after requests and the dozer manager. The
  existing AIPlayer retry timer (+0x158, initially 150) schedules it; the
  existing phase indexes PercentToSave. The pre-transfer cap is not a clamp
  on the amount: a single save can exceed it.
- RW 0x961975 temporarily deposits the entire reserve, checks the request,
  then withdraws the entire reserve (not an assignment restoring old cash).
  RW 0x96190B releases a positive signed `_ftol2` low-word cost-minus-cash
  shortfall only when enough is saved. It does not refund the reserve when
  the subsequent execution fails.
- Request cost is RW 0x97DD6B / 0x9EDC36, exact signed `fild` of the cost:
  heroes use Player's hero-list cost (RW 0x780AD3), ordinary templates use
  calcCostToBuild; KindOf bit 157 returns zero. There is no float32 store
  between cost lookup and the subtraction.
- RW 0x9A1010..0x9A1030 sets a unit request's reserve flag when its
  unmodified template cost (null player/producer, override -1), converted
  with CVTSI2SS, is >= 1000. Heroes and rebuilt structures already set it.
- RW 0x9A0A74's hero affordability uses total money. RW 0x9A1A7D..0x9A1AA2
  withdraws min(dozer cost, saved) before queueing, not merely the shortfall.

The balance and cap are hashed by `AIStatCollector::addToHash`; the timer
is also hashed. Current coverage is `ai5 money saver: *` in
`test_skirmish_ai_upgrades.cpp`, not the old branch's reserve tests.
The old branch's tagged non-default hash block and dedicated reserve
save/load test are not imported here. Native retail snapshot parity is
not established by command-log reconstruction.

**Existing AI5 simulation/hash behavior, not a change in this lane:** saver state changes from the first due AI
frame (normally 150), expensive unit requests set their reserve flag, and
reserved construction/training can spend saved cash. This can change AI
build order and later random draws. Pinned vectors are deliberately untouched.

**S-413 remains open outside this closed runtime subgap:** expansion bases

LumberMillBuild (0x9B9E06) and StructureCreep (0x9BA3C2).
RW 0x9ED351 is the FORTRESS heuristic, already ported by AI5 (S-1876).
The formerly unidentified request is AIExpansionScience: its check
RW 0x9ED764 and execute RW 0x9ED8C4, including withdrawal RW 0x9ED951,
are already ported by AI5. Do not reapply the old reserve implementation.
