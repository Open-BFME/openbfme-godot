# RW 0x90313E — GameSlot::disconnected (S-1064)

## Identity, layout and boundary

This is the ZH/BFME2 `GameSlot::disconnected` predicate, not the operation that
leaves a game. BFME2's `GameNetwork/GameSlot_disconnected.cpp` explicitly names
the method and m_disconnected at +0x48; `DisconnectManagerO1.cpp` identifies
the same byte written by DisconnectManager::disconnectPlayer. Target evidence
is the supplied pack plus direct disassembly, with PLAN rule 9 / S-001's
modified-executable caveat. The reachable body is **27 bytes**,
0x90313E..0x903158. The advertised 59-byte inventory range also includes
unrelated setters/getters beginning at 0x903159, 0x903166 and 0x903173.

## Recovered C++

```cpp
// RW 0x90313E..0x903158
bool GameSlot::disconnected() const
{
    return isHuman() && m_disconnected; // RW 0x8009A7; byte +0x48
}
```

`isHuman` is tier-A GameSlot::isHuman (BFME2 0x7FF0F1,
`GameNetwork/GameInfo.cpp`): state dword +4 equals SLOT_PLAYER (6).
The predicate returns exactly 0 or 1 in EAX. It tests only AL from isHuman,
short-circuits before the flag load for nonhumans, and treats any nonzero byte
as true. No null guard, mutations, floating point, allocation or network I/O.

## Callers and timing

The pack reports references from RW 0x903AC0 (GameSpyStagingRoom results-packet
generation), RW 0x9270AD (score-entry construction), and RW 0x9CFA65
(StatsReporter online results processing). The latter two donor matches are
context, not proof of the entirety of those larger functions. The score
call at RW 0x927183 was checked directly: for a nonnull slot, true sets the
entry result +0x10 to 2, bypassing the later defeat/victory checks. Null or
false continues through those checks from default 3. This predicate does not
itself determine a loss, disconnect a peer or transfer an army.

## Port and remaining stop

The lobby slot already supplies `isHuman`; live Network::SlotData already
owns the disconnection flag. The port deliberately does not duplicate that
mutable flag in a serialized lobby record. SkirmishGameSlot::disconnected
takes the live flag and applies the recovered conjunction. NetGameSession maps
disconnected human slots to the existing slotPlayerIndex mapping; GameWorld
passes those indices to ScoreScreenData::build instead of an always-empty
vector. ScoreScreenData already gives result 2 priority over defeat/victory.

**INFERENCE / adapter:** the two engine objects jointly represent retail's
GameSlot; no ABI-layout equivalence is claimed. A live spectator now derives
the flag from the native relay log's existing DROP/REJOIN events at its playback
boundary, instead of returning no disconnected indices merely because it has
no Network instance. DROP applies at the start of its frame; REJOIN clears the
flag after its frame completes. LEAVE and DESTROY do not set the flag.

`RelayLog::assemble` collects drops before appending executed rejoins, so its
membership vector is not time-sorted. The score query compares effective frame
boundaries, with a new-incarnation drop winning at the same boundary as the
completed rejoin (matching assemble's applyDrops). It neither consumes future
events nor changes simulation state. Slot-to-player mapping and the human-only
predicate remain the same as the live path. This is an **enhanced-profile
adapter**, not a claim that retail supports this relay or online rejoin.

S-1064 remains for replay result restoration, Living World and early quit.
The current native Recorder format preserves commands, hashes, profile changes
and recording errors, but not network disconnection flags. RelayLog::writeReplay
also omits membership. A SELF_DESTRUCT command is not proof of disconnection
(surrender and graceful exit use it too), so no such heuristic was added.
Old replays cannot reconstruct a flag which was never recorded. Closing this
gap needs explicit recording/playback metadata, not a change to retail replay
bytes or simulation commands.

The asset-free test `rotwk-c end: disconnected requires a human slot and the
network flag` covers false/true flags for open, closed, all represented AI
states and human. It cannot pass against the old API. Live score integration
also needs asset-equipped Godot/net-end testing; it is not established by
that predicate test. This changes presentation of disconnected live humans to
result 2, not lockstep state or simulation hashes. Pinned vectors unchanged.

## Early quit follow-up: recovered chain, still not ported

RW 0x9219C5..0x9219F2 in AptQuitMenu's destructor takes this branch only on Exit,
with nonnull GameLogic, unsigned frame **less than 6** (constant RW 0xBFD298),
mode 1 or 5, and nonnull Network. At frame 6 or without those guards it falls
through to the normal/campaign branch. The virtual call +0x94 maps to
Network::quitGame, RW **0x65DF2E** (tier A, BFME2 Network.cpp rva 0x25E233).

The recovered chain is:

```cpp
// RW 0x9219C5..0x9219F2, after the Exit and GameLogic guards
if (logic->getFrame() < 6 && (mode == 1 || mode == 5) && TheNetwork)
    TheNetwork->quitGame();
// otherwise: RW 0x9219F4 onward, not this fast path

// RW 0x65DF2E..0x65DF79 (the map's 176-byte extent contains later functions)
void Network::quitGame()
{
    if (m_pConMgr)
        m_pConMgr->rva004D0E8B(); // RW 0x8D526B: rva004D00BB(0)
    GameMessage *message = MessageStreamSubsystem->appendMessage(0x1D);
    // The supplied image has a literal absolute 0x114 read when GameLogic is null.
    // With the live GameLogic of this caller, the following append always occurs.
    message->appendIntegerArgument(2);
    slot39(0); // RW 0x65DF6B: Network vslot +0x9C; not resolved here
    m_state = 3;
}
```

RW 0x8D526B is a **seven-byte** wrapper (the map's 216-byte extent includes
unrelated following bodies). It calls RW 0x8D449B with zero. That method creates
the 0x24-byte message whose constructor RW 0x8D9DAA sets command type **7,
REQUESTPLAYERLEAVE**, sets local slot at +0x1C and argument zero at +0x20,
timestamps it, sets execution frame to -1, sends directly to mask 0xFF and
flushes via RW 0x8D3CE2. The donor's present-unmatched
ConnectionManager::quitGame (DISCONNECTPLAYER) is **not** this target path.

The port's NetGameSession::finish uses the ZH-style scheduled PLAYERLEAVE path,
and its protocol does not implement REQUESTPLAYERLEAVE / INFORMPLAYERLEAVEFRAME
negotiation. Reusing finish or the disconnect-screen vote path would not port
this chain. The Godot Exit still sends SELF_DESTRUCT on the normal path before
clearing; this early-frame ordering remains an explicit gap. The binary
provenance caveat at the top continues to apply.

## Remaining prerequisite audit

The map also resolves the receive side: RW **0x8D376A** is tier-A
`ConnectionManager::rva004CF35D` (BFME2 RVA 0x4CF35D); RW **0x8D40E6** is
tier-A `BFMEConnectionManager::processInformPlayerLeaveFrameCommand`
(BFME2 RVA 0x4CFD06). Their source is in GameNetwork/Rva004CF35DFunc.cpp and
GameNetwork/BFMEConnectionManager_processInformPlayerLeaveFrameCommand.cpp.
The former validates a slot below eight and latches its first leave request
and requested value. The latter reads the leave frame and leaving slot,
updates the sender's latest frame under the current-frame/run-ahead bound,
and requests missing frames through the leave frame when appropriate.
These are a negotiation and recovery protocol, not two aliases for PLAYERLEAVE.

The current `NetPacket` enum/dispatch has no type-7/type-8 handlers or the
request-latch/negotiated-leave state. It also uses the enhanced encoding
(S-721), rather than the retail direct-send/flush and command-ID transport.
Closing early quit therefore requires that state machine and transport
integration, plus resolution of Network vslot +0x9C and the game-clear/menu
ordering. Adding only the `< 6` check or calling `finish()` is not equivalent.

Recorded results remain independently blocked: `Common/Recorder.cpp`
version 6 has FRAME, HASH, END, LOST and PROFILE records, not network
membership, and `RelayLog::writeReplay` discards that information even when
the source relay log had it. Existing such recordings contain no evidence
that distinguishes a disconnect from surrender/graceful exit. Future
enhanced recordings need a versioned membership record or companion metadata
with frame-boundary semantics; retail recordings must not be modified (PLAN).
This is a new recording-format/integration prerequisite, not a flag that can
be recovered by another scan of RW 0x90313E.

The Living World exit path remains blocked on the missing campaign state
model. No new S-1064 behavior is claimed by this audit. The live-human and
relay-spectator adapters from the preceding commits remain the covered paths.
