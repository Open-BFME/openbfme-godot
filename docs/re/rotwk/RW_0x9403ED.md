# RW 0x9403ED — ControlBar double-click gate (S-1954)

## Identity and evidence

ControlBar member with one Object pointer parameter; this is not read. The map
omits a counterpart, but BFME2's authored
`Code/GameEngine/Source/Common/Rva005399D0Check.cpp` contains the same gate,
`ControlBar::rva005399D0Check` (BFME2 0x9399D0). Its original descriptive name
remains unknown. Target behavior below is checked against the supplied pack and
image, with the modified-image caveat of PLAN rule 9 / S-001.

RW 0x6A6AE5 installs InGameUI vtable 0xC134E8. Reading its slot +0x188 gives
RW 0x69D90C, mapped to **InGameUI::selectMatchingAcrossScreen** (BFME2 0x69CEBB,
`GameClient/InGameUI_selectMatchingAcrossScreen.cpp`). The target body builds
the viewport region and dispatches +0x190 (`selectMatchingAcrossRegion`);
it reports NothingSelected for -1, SelectedAcrossScreen for nonzero, and returns
the count. It is **not** the map-wide selection slot +0x18C (RW 0x69DA23).
This proves the base InGameUI implementation; a derived vtable can override it.

## Exact behavior / recovered C++

```cpp
// RW 0x9403ED..0x94042F. Descriptive target name; no member offset on ControlBar.
int ControlBar::rva005399D0Check(Object *obj)
{
    if (!obj) return 0;
    if (!obj->isLocallyControlled()) return 0; // RW 0x68B749, tier A
    if (!obj->isSelectable()) return 0;        // RW 0x68DE58, tier B
    if ((unsigned char)obj->rva0028D481()) return 0; // RW 0x68DAD6, tier A
    TheInGameUI->selectMatchingAcrossScreen(); // global 0xDE4830, slot +0x188
    return 1; // independent of the virtual's result
}
```

RW 0x68DAD6 loads Object +0x04 (ThingTemplate), then extracts bit 7 of
template +0x108: KindOf STRUCTURE. This agrees with the donor's Object layout
and `InGameUI_selectMatchingAcrossMap.cpp`; no hero-type filter is present.
RW 0x68DE58 was checked, not assumed identical to its tier-B donor:
template +0x10F bit 2 bypasses all subsequent checks; status 3 rejects;
template +0x642 controls the effectively-dead (+0x458 bit 0) rejection;
template +0x111 bit 1 rejects; Object +0x454 is the selectable byte, with an
InGameUI +0xC0 command-type 0x18 / template +0x10F bit 4 override. The BFME2
offsets for the shifted fields are +0x632, +0x438 and +0x434 respectively.
No floats, mutations of Object, or modifier-key tests occur in this gate.
Crucially, the Object parameter is **not** passed to the virtual and this gate
does not replace the current selection with that object.

## Caller / timing

Only pack caller: CommandTranslator RW 0x81F791 calls at RW 0x81F828 on the
double-click path. It refuses force attack (InGameUI +0x8B8) and non-point
regions; picks SELECTABLE (4), non-forced; gets Drawable +0xFC (Object).
Status 38 causes promotion via Object +0x27C or fallback ObjectID +0x78,
provided the linked object's contain +0x258 returns nonnull at slot +0x7C.
Then the ControlBar global 0xDE7744 receives this gate. Status-38 ownership is
the horde/contained-object route (**INFERENCE** here; the offsets and tests are
proven). The caller ignores the gate result. These are client selection inputs;
selection messages subsequently affect the simulation's selected groups.

## Port and remaining stop

Ported the missing STRUCTURE rejection, and the local-before-selectable order,
into the existing double-click handler. Regression: `rotwk-c pick retail: a
structure double click does not expand selection` in `test_hud_input.cpp`.
It requires the retail installation and therefore runs on asset-equipped CI.

## Follow-up: translator, current selection and selectability

The translator call site is RW 0x81FBE4..0x81FBEE: call RW 0x81F791 and jump to
the common return. It is separate from either order-click path, independent of
alternate-mouse mode. The port now runs it in CommandTranslator (after
SelectionTranslator), without reseeding from the pick, an Alt map-wide scan,
Shift save/restore, or an extra MSG_AREA_SELECTION. The click gates a scan of
the **existing selection's templates**. An empty selection stays empty.

The pick now returns the raw drawable's object for this caller, instead of the
shared ZH selectionRepresentative promotion. Status 38 is **HORDE_MEMBER**.
Object +0x27C is containedBy, +0x78 is producer ID, and contain slot +0x7C is
getHordeContainInterface (the same accessor already ported by HORDE-1). Failure
to resolve the horde or its interface stops the handler. Other statuses do not
take this promotion route.

RW 0x68DE58 is now shared between PlayerCommands and HudObjects rather than
HudObjects requiring SELECTABLE and rejecting NO_SELECT (neither is a test in
this function). Its complete target order is:

1. KindOf ALWAYS_SELECTABLE (template +0x10F bit 2): true immediately.
2. Status UNSELECTABLE (3): false.
3. Effectively dead (+0x458 bit 0), unless KeepSelectableWhenDead (+0x642): false.
4. KindOf DRONE (template +0x111 bit 1): false.
5. Script-selectable (+0x454), **or** GUI command SPECIAL_POWER (0x18) with
   KindOf WALK_ON_TOP_OF_WALL (template +0x10F bit 4).

The last exception overrides only the script byte, not the earlier gates.
The constructor RW 0x69A648..0x69A652 initializes +0x454 from template KindOf
bit 1 (SELECTABLE). The old port initialized it universally true and relied on
the HUD's extra KindOf gate. The flag now starts with the recovered value;
an explicit script setter can override it for a non-SELECTABLE template too.
Native hashing records deviations from that template-derived default, retaining
the existing false-override tag and adding a distinct true-override tag. This
is the port's hash encoding, not a claim about retail CRC serialization.
The adapter still rejects already-destroyed engine objects before accessing
their state. The client supplies the GUI context; logic-only squad recall does
not import nondeterministic client state (remaining S-280 caveat).

`rotwk-c pick retail*` now tests the structure guard, existing-selection rather
than picked-type expansion, empty selection, force attack, no extra selection
messages, ignored Alt, and the wall override versus UNSELECTABLE. These run
through the retail-backed engine HUD, not against a running retail executable.

At this stage S-1954 remained for the other pick differences (model-draw override/status bits,
0x40 collision type, cast force-attack flag) and Living World input lock. The
0x40 SCRIPT_TARGETABLE portion is implemented in the follow-up below. The
region scan is the existing ZH-based implementation moved to InGameUI: full
BFME contained-template matching and drawable traversal ordering are still
S-1202, not claimed fixed by relocating it. No pinned vectors were edited;
selection/command-stream hashes can change for inputs whose old double-click
handler replaced the selection or emitted MSG_AREA_SELECTION.

## Follow-up: SCRIPT_TARGETABLE and dead collision exemptions

RW 0x4B58C3 loads EDI from Drawable +0xFC, the **Object**. Consequently
RW 0x4B5988 reads Object +0x457 bit 4, the already-ported SCRIPT_TARGETABLE
script flag, not a separate Drawable field as the earlier stop text stated.
The render object's Set_Collision_Type call replaces the complete type with
0x40. It runs after FORCEATTACKABLE and CLICK_THROUGH, before death clearing.
RW 0x710845 / 0x71084A start context masks at 0x44 / 0x64; adding 0x40 only
to collisionTypeOf without restoring these masks would still lose these picks.
The double-click and explicit GUI-object-target masks remain SELECTABLE-only
(plus the latter's shrubbery/rock options), so neither gains this type.

RW 0x4B599F..0x4B59DE exempts BRIDGE, BRIDGE_TOWER and the template byte
KeepSelectableWhenDead (+0x642) before either rubble or death clearing.
The death test is exactly Object +0x458 bit 0 (`Object::isEffectivelyDead`),
not a new calculation from health. The port now uses this flag and the
KeepSelectableWhenDead exception. The renderer-specific rubble test at
RW 0x4B59BD reads **Drawable +0x258 bit 5**; the existing object's RUBBLE
condition remains an adapter, not a recovered replacement for that state.

The retail-backed `rotwk-c pick retail: script targetable*` and
`rotwk-c pick retail: KeepSelectableWhenDead*` cases cover type replacement,
context versus double-click/GUI masks, death-clearing order, and the template
exception. These can move selection/input hashes for affected scripted/dead
objects; no pinned expected vector is edited.

Remaining blockers after this gap:

* W3DModelDraw +0x214 is a per-model override, checked against -1 or 1
  before the KindOf default. No equivalent per-draw selectable override is
  represented in HudObjects; mapping the object's script-selectable flag to
  it would conflate different states.
* Drawable +0x258 bit 5 and draw module data +0x6A (final unconditional
  collision suppression at RW 0x4B59E4) need renderer-side state integration.
  They must not be represented by another effectively-dead check.
* The force-attack argument sets the retail ray-cast flag at RW 0x48ABFF.
  The port casts template cylinders, not the retail W3D polygon/hidden-mesh
  hierarchy (S-284/S-1200), so threading a boolean alone would not implement it.
* Living World input state and S-1202 contained-template/drawable traversal
  ordering are still missing; the corrected masks do not close those systems.

All address findings retain the supplied modified-image provenance caveat.
