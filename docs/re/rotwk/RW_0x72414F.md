# RW 0x72414F — GadgetComboBoxSetMaxDisplay (S-1917)

## Identity and layout

This is the ordinary **text combo** setter `GadgetComboBoxSetMaxDisplay`, not
an image-combo color/hero field or a number of heroes. Recovered from the target
pack and its callers, with PLAN rule 9 / S-001's modified-image caveat.
RW 0x9A5E08 is GameWindow::winGetUserData (tier A, BFME2 0x9C4ACD,
`GameClient/GUI/GameWindow_winGetUserData.cpp`): GameWindow user data at +0x2C.
The returned ComboBoxData has isEditable at +0 and maxDisplay at +4, as in the
byte-matched donor `GameClient/GUI/Gadget/GadgetComboBoxSystem.cpp`.
The port's native layout differs; use its named member, not a byte cast.

Identity cross-check: the tier-A caller GameWindowManager::gogoGadgetComboBox
(RW 0x6C2C46, BFME2 0x6C2AF8,
`GameClient/GUI/GameWindowManager_gogoGadgetComboBox.cpp`) calls this at
RW 0x6C2F5D with the creation data's +4, immediately after SetMaxChars (+8).
Its donor names both the field and setter. The consumer's dropdown layout uses
min(entryCount, maxDisplay) and scroll controls when entries exceed the limit.

## Exact recovered behavior

```cpp
// RW 0x72414F..0x72415F (17 bytes, cdecl, caller cleans two stack arguments).
void GadgetComboBoxSetMaxDisplay(GameWindow *comboBox, int maxDisplay)
{
    ComboBoxData *data = (ComboBoxData *)comboBox->winGetUserData(); // RW 0x9A5E08
    data->maxDisplay = maxDisplay; // +4
}
```

No guard, clamp, sign test, immediate resize, selection change or notification.
Null window/user data is not supported. No floating-point or simulation work.

The lobby argument is **max(8 - slot, 4)**, NOT the previous stop's
`min(slot, 4)`. RW 0x8402C1 subtracts the argument from 8, compares signed to
4, and returns the larger. Tier-A donor: Rva0043DDF8 in
`GameClient/GUI/MpGameSetupSlots.cpp` (BFME2 0x83DDF8). For slots 0..7 the
limits are 8, 7, 6, 5, 4, 4, 4, 4. The helper has no slot-range check.

## Port / tests / stop closure

The generic setter already existed with exact assignment semantics. Added the
missing slot-derived limits to faction, handicap and hero setup, retaining
the hero-system guard. The assignment only sets the display limit; the current
`SkirmishGameSetup::handicapEntries` separately supplies 0% through -95% in
steps of -5%, and `AptSkirmish` populates the combo from those entries. Handicap
population is no longer an S-178 gap. Color image combos are unchanged.
Closed S-1917, whose only remaining gap was this setter argument. Hero record
and faction inferences remain under S-1406, not silently promoted to facts.

Tests: `rotwk-c lobby retail: handicap and faction dropdown limits follow the
slot` covers slots 0, 1, 4, 7. The existing Create-a-Hero combo test now checks
the local hero's eight-row limit (ten actual choices). Both require retail
assets and run on asset-equipped CI. No simulation/hash-vector change.
