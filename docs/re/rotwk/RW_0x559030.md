## Recovered contract

This is a character-advance layout algorithm, not the port's current
whole-word `FontMetricsSource::textWidth` wrapper. Its normal font path asks
`FontCharsClass` for each character record. Missing or zero-width records
advance zero; Thai-range characters use width plus extra spacing, while other
characters use width minus pixel overlap minus character overhang.

The hard-wrap comparison is inclusive and conditional on the hard-wrap flag:

```cpp
// RW 0x559030, condition only; not a complete replacement layout routine.
if (useHardWordWrap && wrapWidth != 0 && x + charSpacing >= wrapWidth)
    beginNewLine();
```

Spaces, newlines, NUL and character 0x95 participate in break handling. Space
and 0x95 handling looks ahead through the next word's character advances. When
that lookahead reaches the wrap width it starts a new line and skips the break
characters. A non-wrapping 0x95 is discarded. A newline resets the horizontal
position and skips following spaces. This is not equivalent to trimming both
ends of each line, nor to accepting a whole word whenever its width equals the
remaining width.

When hotkey parsing is enabled, an ampersand before a printable character other
than the break characters is consumed, the hotkey position is recorded, and
the glyph is handled through the hotkey path. Lookahead and drawn-glyph spacing
must preserve that operation order. Final extents include the font overlap;
centering shifts generated chunks rather than changing the character advances.
The caller's hard-wrap/hotkey/centering flags remain part of the integration
contract; this audit does not substitute one fixed mode for every display string.

Thai characters select the separate RW 0x5587C0 path (mapped BFME2 RVA
0x00158E90). It calls the GDI glyph-index path at RW 0x553F20, can choose a
fallback font when glyphs are missing, and walks glyph-index widths and extra
spacing alongside the text. Treating Thai UTF-16 units as ordinary aggregate
Godot text measurements does not reproduce this behavior.

## Concrete port blocker — S-176 / S-3700

`FontMetricsSource` currently supplies only font height, whole-string width and
wrapped height. `GodotHud6Draw.cpp::HelpFontMetrics` uses Godot string sizing and
`AptMenuPlayer::font_cell`; neither exposes the retail per-character width,
extra spacing, pixel overlap, overhang, GDI glyph indices or fallback-font
selection. The cell adjustment is not a source of those missing values.

Exact closure requires those font inputs and the display-string mode flags,
then a character-level port with non-Thai/Thai, equality-boundary, hard-word,
repeated-space/newline, 0x95 and hotkey tests against measured target output.
Synthetic monospace metrics could test a partial algorithm but cannot prove
the requested retail wrapping. Therefore the current inferred wrapper is not
relabeled exact, and no red-to-green closure or rendered capture is claimed.
