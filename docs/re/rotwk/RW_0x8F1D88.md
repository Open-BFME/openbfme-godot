## Ownership and call path

`this` is AITactic, +0x24 owner Player*. Inputs are first Team* and the ending
tactic's float strength; output is a candidate **Object*** (not Team*).
Called at RW 0x8F20D1 by tactic end RW 0x8F2006, before team joining/release.
That caller uses the candidate's team. Thus the existing engine's
AITacticalAI.cpp::findMergeTeam returning AITacticTeam* is an adapter, not the
original ABI. This fits S-895's remaining merge support and S-418's player
record ordering; no duplicate unnamed stop is needed. Supplied image S-001
caveat applies; no direct patched-section calls.

Player-info RW 0x6A9999 (donor Rva002A8F24::rva002A8F24) supplies +0 army
collection; its vector +4 is counted by RW 0x945ADA and accessed by
RW 0x65BCEF (Rva0025BFF8ObjectGetter.cpp). Player +0x30C default Team*,

Object +0x38 position. `Team::rva0039E5B9` RW 0x7A0ECD computes the first
team's center. RW 0x68B36F is Object::rva0028ACA0 (active goal object through
Object +0xA4), called twice when non-null. Original helper names below are

(Object* push_back), RW 0x430170 (free). Do not infer element type from the
constructor's shared-template donor label. All normal/exception exits clean

on collection membership. It also does not deduplicate hordes sharing a team.

strict: equality does not merge. Draw upper bound is `counters` as returned,
not capped or normalized here. Source identity is AITactic.cpp, line 0x3FC.

## Existing port / remaining

The engine already has the two-stage candidate scan, distance/order and
line-tagged RNG in `findMergeTeam`, followed by `mergeTeams` at tactic end.
It explicitly stops if the destination tactic lacks a target: the alternate
RW 0x8F1499 path through per-team cached threat RW 0x7A6A20 is not ported.
Formation attack-move at merge remains S-895; BACKLOG-8's ordinary formation
march does not close that attack-march gap (state 61, S-4463). Source collection order is
the player-record subsystem's S-418 dependency, not something this helper
can replace with object-ID sorting. Keep those stops; no duplicate wrapper
or newly claimed full parity. Existing focused AI tests exercise the partial
port; this documentation introduces no simulation/hash change.
