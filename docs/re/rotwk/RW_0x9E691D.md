## Identity, layout and call context

S-1421, supplied image with S-001 provenance caveat. The data reference
RW 0xC8DCCC is the decision vslot reached by AISpecialPowerUpdate for
ATTACK_HEAL_AOE. The actual original class/method name is not recovered;
`AttackHealAoEDecision::decide(Object*)` below is descriptive **INFERENCE**.
Decision +8 = power template, +0x14 = scan radius, +0x18 = distance limit.
Object +0x31C = Team*, +0x38 = position, +0x74 = ID.

Team +0x140 is the ordered power registry queried at RW 0x9E6941 by
RW 0x7A3EF5(power,0). **Any** non-null result rejects this decision, including
the caster itself (unlike Soul Freeze). Team +0x13C is an intrusive list of
orders, with next pointer at node +0, previous at +4, payload at +8. The node
has command +0xC, flags byte +0x13, object ID +0x24. Commands 0x11 and 0x31
are accepted; original enum names remain unproven here, not guessed from ZH.
No direct callee enters the S-001 added sections.

```cpp
{
    // RW 0x9E692A..0x9E69ED
    Team *team = caster->team;
    if (team->lookupPower(power,0)) return false; // RW 0x7A3EF5
    auto it = team->orders.begin();
    Coord3D pos;
    bool found = false;
    for (; it != team->orders.end(); ++it) {
        if (it->command != 0x11 && it->command != 0x31) continue;
        ObjectID id = it->flagByte13 & 0x40 ? it->objectID : 0;
        if (id) {
            Object *target = TheGameLogic->findObjectByID(id); // RW 0x449681
            if (!target) continue; // does NOT fall back to the position payload
            pos = *target->getPosition();
        } else {
            if (!it->getPosition(&pos)) continue; // RW 0x79F922
        }
        found = true;
        break;
    }
    if (!found) return false;
    // RW 0x9E69F3..0x9E6A5E
    caster->rva0028ACDC(&pos); // RW 0x68B3AB, BEFORE testing distance
    Coord3D delta = {subf(caster->x,pos.x), subf(caster->y,pos.y),
                     subf(caster->z,pos.z)};

    if (!(length < x87mul(distanceLimit,0.9f))) return false;
    // RW 0x9E6A64..0x9E6AD7
    auto hits = ThePartitionManager->iterateObjectsInRange(caster->getPosition(),
        radius,0, aliveFilter.And(relationshipFilter(caster->player(),true,4)),1);
    Object *first = hits.next(); // only one next(), not a search over all hits!
    if (!first) return false;

    team->orders.erase(it); // RW 0x7A1C5E
    return true;
}
```

All failure paths return AL=0; all constructed range iterators are destroyed
by RW 0x44A2A5. Only success erases the chosen order, not the registry. A
failed distance/target test does **not** continue to another order or hit.
There is no registry insertion here and no direct random draw. Target
validation may consume random draws in its optional search mode.

RW 0x68B3AB is the BFME2 Object::rva0028ACDC wrapper
(ObjectRvaSmallGetters.cpp): if Object +0xA4 exists, tail-call RW 0x8E28AC
with the position pointer; otherwise do nothing. Its full command-provider
effect must be retained, not replaced with a no-op because its return is unused.

RW 0x79F922 tests payload +0xB bit 0x80 and copies its three position words
from payload +0x10; otherwise it returns false without writing. Relative to
the enclosing list node these are +0x13 and +0x18. The object-ID alternative
uses bit 0x40 of the same byte and payload +0x1C (node +0x24).

The distance vector uses three separate SSE SUBSS operations. Length is the
byte-matched donor `Coord3D::GetLengthEstimate`
(WWMath/coord3d_lengthestimate.cpp), not exact sqrt. Limit multiply is x87
FMUL by the float at RW 0xBDE198 (0.8999999761581421). FCOMIP/JBE rejects
equality and unordered; do not round the product/length to float prematurely.

Alive filter vtable RW 0xC10E20 rejects Object +0x458 bit 0. Relationship
filter RW 0xC1676C (predicate RW 0x66110A) accepts enemies only, mask 4;
range center is the **caster**, not the order position. PartitionFilter::And
RW 0xA394C0 and iterateObjectsInRange RW 0xA39340 have byte-matched donors.
Map labels `BfmeWideResult::next` / destructor name the iterator methods;
`URva004907AAElement::list<>::erase` for RW 0x7A1C5E is shared-template code,
not evidence of a different owner.
