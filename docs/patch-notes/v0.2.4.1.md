# Open BFME — alpha hotfix v0.2.4.1

v0.2.4 could not start a skirmish or the Fords scenario. Both died with
**RETAIL SLICE UNAVAILABLE**: `buildingLifecycle construction facts and phase
animation disagree`.

## What you can do now

Start a RotWK Men skirmish and the BFME2 Fords "Destroy the enemy fortress"
scenario. Both boot.

## What was wrong

A stricter structure-lifecycle check, added to keep static construction honest,
rejected the **legacy Men fortress registry entry**. That objects.json document
authors no construction facts at all (the key is absent) while its construction
phase is still `manual-progress`. The runtime invented a "none" expectation
from the missing key and fail-closed.

Content is unchanged. The runtime no longer asks a lane that never required
construction facts (Men) to prove them. A document that *does* author
construction facts is still cross-checked: a MANUAL/NONE mix still fails.

## Why our gates missed it

Debug builds **fail open** on this class of error: Godot aborts the validating
function, the caller sees an empty error string, and the runner prints PASS
while stderr holds `Invalid access to property or key 'construction'`. The
release / exported build **fails closed** — that is the only place the owner
hit it, and the only place it had never been exercised. The v0.2.4 ship
checkpoint printed the error 11 times in `retail_slice_runner.err` and still
reported `RETAIL_SLICE PASS slice_ready`.

The new slice-start runner boots both owner surfaces (a RotWK skirmish map
and BFME2 Fords) and asserts **zero** `SCRIPT ERROR` / `Invalid access` lines,
so this cannot recur unnoticed.

## How to start it — read this first

**Double-click `run-with-log.bat`.** Not `OpenBFME.exe`.

This build does not find its own content packs; the .bat points it at the ones
in this folder. Starting the exe directly gets you a game that loads whatever
old content is lying around in your user profile, or none.
