# Object shadow maps (S-3304)

The Godot renderer uses directional shadow maps for volume-shadow objects. This is a presentation substitute, not a reproduction of SAGE's CPU-extruded stencil volumes or RotWK's shadow-map shaders. It changes no simulation state or random stream.

## Implemented

- Object-template `Shadow` bits select `SHADOW_VOLUME`, `SHADOW_VOLUME_NEW` and their `OR_DECAL` forms. A model state's shadow description overrides the template; `ShadowForceDisable` wins. Floors, particles and UI models do not become mesh casters.
- Lane MAPCAST-1: RotWK's own shadow map (ShadowLOD High and UltraHigh) has no caster filter on the `Shadow` field: `W3DShadowMapManager::updateShadowMap` (RW 0x47D5C9, BFME2 0x7DC01) renders the scene from the shadow camera through `RTS3DScene::Render`, the shadow rendering method (RW 0x47B1BB) swaps each effect's technique for its `_CreateShadowMap` one, the visibility check culls only hidden, out-of-frustum and shrouded objects, and `MeshClass::Render` (RW 0x54B75D) draws every FX mesh (BFME2 decomp, tier B; RotWK's update, method and mesh render read in the binary). So at High and UltraHigh every model casts: the volume objects and also `SHADOW_DECAL` infantry, cavalry and trees and objects without a `Shadow` field (`ObjectShadow::casterKind`: kind 2, `W3DInstancer::set_instance_shadow_caster`; `set_retail_shadow_mapping` from object_shadows.gd). At Medium only the volume casters' substitute is drawn, as before: retail draws no map there but decal blobs, which remain S-3304. INFERENCE: `ShadowForceDisable` keeps a model out of the map too.
- Each instancer creates shadow-only MultiMeshes lazily. They share the visible mesh, materials and bone palette, but contain only eligible instances. Hidden subobjects, invisible pivots, zero opacity and removed instances are omitted by the same visibility pass. Skinning, alpha cutouts and vegetation sway run through the same vertex/fragment shaders.
- While a shadow map is drawn, casters continue posing outside the presentation camera's frustum: an off-screen object can cast an on-screen shadow. This deliberately trades some pose-culling savings for correct animation; with ShadowLOD Off or Low they are pose-culled like any instance. No new per-object scene nodes are created.
- Opaque W3D surfaces, terrain and roads receive shadows. The custom light function uses only directional-light shadow coverage; it does not replace the existing retail lighting calculations with Godot lighting. UI/standalone W3D instancers do not receive shadows unless explicitly enabled. Terrain selection and radius overlays remain above shadows.
- Lane BLOBSHADOW-1: at ShadowLOD Low and Medium (UseShadowDecals, GlobalData + 0x61; RW 0x50BF7A) the drawables' `SHADOW_DECAL` blobs are drawn as retail's projected shadow list does: W3DShadowManager::addShadow (RW 0x49A2E0) hands SHADOW_DECAL (and an `*_OR_DECAL` form while volumes are off) to the projected manager; the texture is ShadowTexture + ".tga" ("shadow" when empty, RW 0x50BFA6 / 0x50B690), the quad ShadowSizeX / Y along the object's facing (ShadowIsRotatingWithObject, default Yes) moved by ShadowOffsetX / Y (DecalShadowCentre), projected straight down, none ShadowMaxHeight (20) or more above the ground, multiplied into the frame buffer (BFME2 flushDecals 0x109E11, _PresetMultiplicativeShader; the BFME2 decompilation's W3DProjectedShadow.cpp is the donor, tier B). The port draws every visible blob as a quad into one top-down 2D viewport cleared to white (GodotDevice/GodotBlobShadows.cpp, godot/shaders/blob_shadow_quad.gdshader: the canvas keeps retail's gamma values) that covers the camera's ground footprint, and the terrain shaders multiply their gamma colour with it before the decal lists and the shadow split (godot/shaders/blob_shadows.gdshaderinc). A blob follows its drawable: none for a drawable the presented look hides or draws as a fogged ghost (retail: setFullyObscuredByShroud at FOGGED), with no shadows (ShadowWhenDead), fully faded, or without a render object (a horde's Model = None); partial fades do not lighten it (Shadow::setOpacity RW 0x73228B leaves SHADOW_DECAL alone). One blob per drawable.
- Lane BLOBSHADOW-2: a blob without ShadowSizeX / Y (the animals Bear, DeerMale and Dog, the creep lairs, camps) takes twice the half extents of the render object's object-space box (RW 0x50C01D asks vslot 0x110 for it and doubles Extent.X / Extent.Y). INFERENCE (S-3304): the port takes the bounds of the model's drawn meshes in the bind pose from the pick's triangle cache (`DrawablePick::bindPoseBounds`, `BlobShadow::modelExtent`); the HLOD's own box, its hidden meshes and collision boxes are not read, and the drawable's instance scale is not applied.
- Lane DRAWDECAL-1: a live drawable's alpha / additive decal shadow (SHADOW_ALPHA_DECAL, SHADOW_ADDITIVE_DECAL and their _DYNAMIC forms: the catapult shots' glow, the Eye's and the crows' eye, lamps, Sting's glow, the in-game markers) is drawn with the selection decals' shaders after the placement ghost's (`BlobShadow::resolveDecal`, `GameWorld::update_decal_shadows`). The drawables' shadow list projects every decal type as the blobs (BFME2 renderShadows mask 0x2c61), so the ShadowLOD gate with ShadowOverrideLODVisibility (RW 0x50BF7A), ShadowMaxHeight and the offsets are the blobs'. A _DYNAMIC decal fades in from ShadowOpacityStart to Peak over FadeInTime and, when it goes, out from Peak to ShadowOpacityEnd over FadeOutTime where it was last drawn (RW 0x7323CE, 0x50B8C9, 0x508B40). INFERENCE (S-3304): the fade's client clock stands while the game is paused, and a _DYNAMIC decal is not kept while its drawable is hidden.
- The existing main object light supplies the direction. `ShadowLOD` now controls Off/Low (no volume maps), Medium and High (2048) and UltraHigh (4096) directional atlases. Each of the four cascades gets a quarter of the atlas, i.e. RotWK's own shadow map size: the `ShadowMap` block's `MapSize` (retail 1024, RW 0x47B69E), raised to at least 2048 at UltraHigh (RW 0x47B2B5); retail draws no shadow map at Medium, which keeps High's size. Turning the maps off restores Godot's default 4096 atlas. Low's retail decal shadows remain unimplemented. All enabled levels use four cascades, a 4000-world-unit range and 32-bit depth. Changing the setting applies during a game.

## Evidence and limits

The original GPL [ZH W3DShadowManager::setTimeOfDay](https://github.com/electronicarts/CnC_Generals_Zero_Hour/blob/main/GeneralsMD/Code/GameEngineDevice/Source/W3DDevice/GameClient/Shadow/W3DShadow.cpp) uses the first object light. [W3DVolumetricShadowManager::renderStencilShadows](https://github.com/electronicarts/CnC_Generals_Zero_Hour/blob/main/GeneralsMD/Code/GameEngineDevice/Source/W3DDevice/GameClient/Shadow/W3DVolumetricShadow.cpp) multiplies framebuffer RGB by the shadow colour (`DESTCOLOR`, `ZERO`); its alpha is not the blend weight. This implementation applies that multiplier in gamma space, before the final output conversion. Applying this donor composite to RotWK shadow-map coverage is an **inference**, not target-binary verification. This does not reproduce BFME2 High's main-light-only shadow attenuation; all enabled presets currently use the same donor composite. Fully lit pixels retain the pre-shadow output; overlapping casters do not repeatedly darken it.

Godot's [spatial shader documentation](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/spatial_shader.html) distinguishes the light's shadow-pass view from `MAIN_CAM_INV_VIEW_MATRIX`. Camera-facing W3D geometry uses the latter to keep its visible orientation in the shadow pass. Opaque and transparent shader permutations explicitly share instance-uniform indices, so adding reception cannot move the tint slot. The fragment-to-light colour replaces an unused varying, preserving the existing interpolation budget.

Still S-3304: of the SHADOW_DECAL blobs (BLOBSHADOW-1): the optimized trees' own blobs (the tree buffer's RenderTreeShadows, RW 0x4695CE: a radius from the mesh, at most 1200 trees; the 202 live tree templates name no ShadowTexture, which retail resolves to ".tga"), the receivers other than the terrain (walk-on walls, bridges and the water surface, which retail darkens too), the blobs' ShadowOverrideLODVisibility at Off / High / UltraHigh (no retail SHADOW_DECAL row sets it), the two seconds a drawable keeps its blob after it is fogged; dynamic/directional projected shadows, non-self volume variants, per-object sun-angle/height restrictions, shadow-opacity curves, translucent placement ghosts, water reception and transparent W3D reception. The Godot maps use alpha-cutout silhouettes rather than retail stencil geometry. Resolution, bias, cascade filtering and distance fade are Godot presentation choices; they are not retail parity claims. Rendered on Vulkan Forward+ only; Metal, mobile and Compatibility need separate validation.

## Validation

Native tests cover template/state eligibility, force-disable, shader generation/interpolator budget, existing lighting math and the enabled options row. GPU tests:

- `godot/tests/object_shadow_render_test.gd`: actual terrain shader; numeric gamma-space shadow colour, unchanged unshadowed output, moving caster, runtime off.
- `godot/tests/object_shadow_instances_test.gd`: shared-model eligibility, transforms, off-camera animation, hidden subobjects, opacity and removal. Requires retail assets and a real rendering backend for buffer readback.
- `godot/tests/object_shadow_building_test.gd`: a retail barracks on synthetic terrain casts/receives a visible shadow, never adds light, and restores the exact baseline when disabled. Optional `OPENBFME_SHADOW_CAPTURE_DIR` saves local evidence; no game-derived images belong in the repository.
- Existing `shader_test.gd` and `building_render_test.gd`: terrain compositing, real-map rendering and normal-mapped/team-colour building permutations.

Run GPU scripts without `--headless`, with `--path godot --script res://tests/<name>.gd`. Retail tests require `ROTWK_INSTALL` and `BFME2_INSTALL`.
