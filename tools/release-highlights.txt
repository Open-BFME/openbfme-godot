# OPEN BFME - player-facing release notes
#
# One line per thing a PLAYTESTER would notice. Format:
#
#     SECTION|commit|text
#
# The commit is not decoration. tools/Build-PlayableBundle.ps1 resolves it
# against the range the release actually covers and DROPS any line whose commit
# is not in that range. That is what stops this file crediting a build with work
# it does not contain: the worst case is a missing note, never an invented one.
#
# SECTION is one of:
#
#   NEW        something a player can do in this build that they could not do
#              before. Only write this if the commit itself says the thing is
#              reachable - a menu entry, a dropdown, a screen. "It exists in the
#              code" is not this section.
#   FIX        something that was visibly broken for a player and now is not.
#   KNOWN      a known issue: something a player will hit, or work that landed
#              but that nobody has confirmed is reachable. Goes here rather than
#              under NEW so it is neither hidden nor claimed.
#   REMOVED    something a player could do before and now cannot.
#   KNOWN  real work that landed which nobody has confirmed the player can
#              reach in a packaged build. This section exists so such work is
#              neither promoted nor hidden. When in doubt, it goes here.
#
# Write for a playtester, not a developer. No pins, no liveness guards, no
# capability probes - say what changes on screen.
